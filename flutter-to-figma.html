MIGRATION GUIDE

Flutter → Figma
组件迁移地图

你不需要重新学一套 UI 系统。Figma 的 Auto Layout 与 Flutter 的 Widget 树在底层逻辑上是同构的——把「写代码」换成「拖拽 + 面板配置」，肌肉记忆可以直接平移。

02

Figma 独有的 6 个概念

/01

Frame vs Group

FRAME / GROUP

Group 只是打包图层，没有尺寸语义；Frame 才相当于 Flutter 的 Widget——可设 Auto Layout、裁剪、约束。

做布局永远用 Frame，别用 Group。
/02

Component / Instance / Variants

COMPONENT SYSTEM

Component ≈ StatelessWidget 类定义；Instance ≈ 调用；Variants ≈ 命名参数，如 type=primary/secondary × state=default/pressed。

命名用斜杠分层：Button/Primary/MD，资产面板自动生成树形结构。
/03

三种尺寸模式

HUG / FILL / FIXED

内容决定尺寸 → Hug；父容器分配 → Fill；写死像素 → Fixed。同一下拉菜单的三个选项。

对应 MainAxisSize.min / Expanded / SizedBox。
/04

Constraints 约束

CONSTRAINTS

子元素相对父 Frame 的行为：Left / Right / Center / Scale / 左右同时拉伸。拖宽 Frame，设置正确的元素自动跟着拉伸。

Figma 版的「自适应」，对应 LayoutBuilder 组合拳。
/05

Styles vs Variables

DESIGN TOKENS

Styles 适合文字/颜色/阴影；Variables 是真·设计令牌，可绑定到 padding、gap、圆角、可见性等。

从一开始就用 Variables 建令牌，命名对齐 Flutter（color/primary、spacing/16），导出 Dart 常量零翻译成本。
/06

Layout Grid

LAYOUT GRID

叠加在 Frame 上的可视化参考网格（8pt 网格、12 列栅格），只辅助对齐，不参与实际布局。

关键区别：它是标尺，不是 Auto Layout。
03

三步迁移路径

用 Auto Layout 复刻一段你写过的布局

比如「头像 40×40 + 标题/副标题占满 + 右侧箭头」的列表项：外层 Frame 横向 + Padding 16 + Gap 12；头像 Fixed 40×40；文字区纵向 + Gap 4 + 宽度 Fill。一一对应你的 Row → SizedBox → Expanded → Icon。

用 Variants 重建一个组件状态机

做一个 Button 组件，定义 type × state 共 6 个 Variant。把过去写 MyButton(type:, onPressed:, enabled:) 的「参数思维」迁移到「变体思维」就到位了。

建立 Variables 令牌库

照 ThemeData 的结构建：color/primary、typography/heading/1、spacing/4/8/16/24、radius/md。命名对齐 Flutter，未来导出 JSON 转 Dart 常量几乎是直接复制。

04

新手陷阱清单

✕

不要用 Group 做布局 —— 只用 Frame + Auto Layout，否则一切响应式都会失效。

✕

不要手动拖 x/y 坐标对齐 —— 横/纵关系的元素一律用 Auto Layout，等于不要什么都套 Stack + Positioned。

✕

先建 Variables 再画界面 —— 不然做到一半要改主题色，会哭。

✕

组件命名用斜杠分层 —— Button/Primary/LG 而不是 primary_button_large。

✕

多用 Fill 而不是 Fixed —— 这是 Flutter「约束思维」带来的天然优势，很多设计师反而会写死宽度。

最难的是布局思维——你已经在 Flutter 里练过了

整个迁移通常 1–2 周完成主力切换，剩下只是图形编辑、原型交互与协作交付这些纯工具层面的事。
